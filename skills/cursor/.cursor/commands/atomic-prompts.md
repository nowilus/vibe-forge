# /atomic-prompts — Cursor slash-command

> Turn a loose one-line idea into a fully-contextualised, re-runnable atomic prompt file in `atomic-prompts/NNNN-<slug>.md`.
>
> **You (the LLM) do not implement the idea inline.** You only generate the prompt file and stop.

---

## When you (the LLM) are invoked

Any of the following invocations triggers this skill:

```text
/atomic-prompts <free-form idea>
```
```text
use the atomic-prompts skill for "<idea>"
```
```text
run /atomic-prompts on this: <idea>
```
```text
/atomic-prompts
<multi-line idea body>
```

Other agent rule files in this project (`.cursorrules`, `.cursor/rules/00-project-anchor.mdc`, `CLAUDE.md`, `AGENTS.md`, …) explicitly route these invocations here.

---

## Behaviour contract

1. **Read context first.** Before generating, read `PROJECT_MAP.md`, `STATE.md`, and `PROJECT_RULES.md`. Then the topic-specific rule file (e.g. `DESIGN.md` for UI ideas, `DATABASE.md` for schema ideas). Do not full-scan the repo.
2. **Resolve next ID.** Scan `atomic-prompts/` for files matching `^\d{4}-`. The next ID is the highest existing number + 1, zero-padded to 4 digits. Start at `0001` if the folder is empty.
3. **Build a slug.** Lowercase, hyphen-separated, ASCII, ≤ 60 chars, derived from the user's idea.
4. **Generate the file.** Write to `atomic-prompts/<ID>-<slug>.md` using the schema in section "Output schema" below.
5. **Print a short confirmation** in chat. Format:

   ```text
   Created: atomic-prompts/<ID>-<slug>.md
   Acceptance criteria: <count>
   References: PROJECT_MAP.md §<n>, STATE.md §<n>, PROJECT_RULES.md §<n> [, other]
   ```

6. **Stop.** Do not start implementing. The user will run the generated file as the next prompt.

---

## Hard rules

- ❌ Never implement the idea inline.
- ❌ Never write to files outside `atomic-prompts/`.
- ❌ Never duplicate the content of `PROJECT_MAP.md` / `STATE.md` / etc. — link to them instead.
- ❌ Never skip sections 7 / 8 / 11 silently. If they do not apply, write `**N/A** — <one-line reason>`.
- ❌ Never invent file paths that do not exist in `PROJECT_MAP.md`. If you need to suggest a new file, mark it `(new)`.
- ✅ Always include verifiable acceptance criteria (no "looks nice", no "is fast").
- ✅ Always include the doc-updates checklist (section 10).
- ✅ Always reference the source-of-truth file the change depends on.
- ✅ Prefer fewer, sharper acceptance criteria over many vague ones (target: 4–10 per prompt).

## Examples of good / bad input → output

### Good

User: `/atomic-prompts Add Google login to the auth screen`

You: read `PROJECT_MAP.md` § "Routes / screens", `STATE.md` § "Implemented features", `PROJECT_RULES.md` § Security, the auth provider's notes in `DATABASE.md`, then write `atomic-prompts/0007-add-google-login-to-the-auth-screen.md` with concrete file references (e.g. `src/routes/auth/sign-in.tsx`, `src/lib/auth/providers.ts`) and acceptance criteria like:

- [ ] "Sign in with Google" button visible on `/sign-in`, labelled per `DESIGN.md` button rules.
- [ ] OAuth callback returns to `/auth/callback` and redirects to `STATE.md`-defined post-login route.
- [ ] Google profile name + email stored on the user row; no other PII pulled.
- [ ] Failed OAuth shows the standard error toast pattern from `DESIGN.md`.
- [ ] `.env.example` updated with `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET`, with comments.
- [ ] `CHANGELOG.md` appends a `### Security` line: "Added Google OAuth provider; client secret stored in <secret store>".

### Bad (do not do this)

User: `/atomic-prompts Add Google login to the auth screen`

You: start writing `sign-in.tsx`. ❌ Stop. Always generate the prompt file first.

## Notes for advanced users

- If the user's idea is **too vague to localise** (e.g. "make it better"), ask **one** clarifying question with 3–4 candidate sub-ideas, then proceed.
- If the user's idea would touch **>5 files**, suggest splitting into two atomic prompts and ask which to generate first.
- If the user's idea **conflicts with `PROJECT_RULES.md`** (e.g. introduces a new dependency), flag the conflict and ask before generating.
